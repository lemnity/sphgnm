# Журнал решений и граблей

Зачем файл. Половина работы здесь — не «сделать красиво», а «не сломать снова
то, что уже чинили». Ниже: почему визуал устроен именно так, какие ошибки уже
были пойманы и как их воспроизвести, и что осталось нерешённым.

README описывает **проект**. Этот файл описывает **решения**: цифры, причины и
цену ошибки. Правите визуал — сверьтесь с разделом «Грабли», там половина
ловушек стреляет молча.

## 1. СОСТОЯНИЕ

> Актуально на конец сессии. Если давно — сверьтесь с `git status`.

Первый экран собран заново и **выложен** (push в `main` → GitHub Actions →
Pages). Что изменилось:

- **Лучи** — фрагментный шейдер на WebGL (CodePen `2025-08-10light-rays/`, MIT)
  вместо прежней CSS-механики из шести столбов. Пучок из одной точки за правым
  верхним углом, вершина за кадром, плавное свечение.
- **Фон** — моховая стена, нарастающая броуновским движением (CodePen
  `moss-by-brownian-motion/`, MIT), поверх фотографии героя.
- **Росток** — золотой (`--brand-gold`, исключение из палитры).
- Подложки первого экрана и шапки перенастроены под осветлённый фон, контраст
  проверен замером (см. §4).

Обе папки-исходника лежат в репозитории как справка: там же лицензии MIT и
авторство. **Их подпапки `dist/` в репозиторий НЕ попали** — под общее правило
`dist/` в `.gitignore`. Нужен весь исходник — берите по ссылкам на CodePen из
README внутри папок; для работы достаточно `src/`.

Выкладка:

```bash
npm run typecheck && GITHUB_PAGES=true npm run build   # НЕ при запущенном dev, см. грабли §4
git add -A && git commit && git push origin main
```

Отдельно висит **`stash@{0}`** — ранняя работа (сквозной рост мха по прокрутке +
перевод комментариев на английский), откаченная по просьбе. Правит те же файлы,
что и текущий герой, поэтому `git stash pop` даст конфликты.
Посмотреть: `git stash show -p stash@{0}`. Удалить: `git stash drop stash@{0}`.

## 2. ПАЛИТРА

Четыре фирменных токена из гайдбука плюс лайм из присланной палитры.
Живут в `components/sphagnum-styles.tsx`, блок `.sph`.

| Токен | Hex | Где работает |
|---|---|---|
| `--brand-ink` | `#141816` | тёмные секции, текст на светлом |
| `--brand-cream` | `#F4F1EA` | светлые секции, текст на тёмном |
| `--brand-moss` | `#3E5042` | акцент **на светлом**, заливки кнопок |
| `--brand-sage` | `#8AA18A` | акцент **на тёмном** |
| `--brand-lime` | `#BAE14B` | бабочки; только на тёмном |
| `--brand-gold` | `#D7B15E` | **исключение из палитры**: только прорастающий знак в фоне героя, только на тёмном |

### Правило, которое нельзя перепутать

Контрасты считаны, не на глаз:

| Пара | Контраст | Годится? |
|---|---|---|
| Cream по Ink | 16.2:1 | да |
| Sage по Ink | 6.6:1 | да |
| Cream по Moss | 7.6:1 | да |
| Moss по Cream | 8.7:1 | да |
| **Sage по Cream** | **2.5:1** | **НЕТ — провал AA** |
| **Lime по Cream** | **1.5:1** | **НЕТ** |

То есть: **на светлом акцент = Moss, на тёмном = Sage или Lime.** Поменять
местами нельзя — мелкий текст станет нечитаемым.

**Золото — осознанное исключение, по прямой просьбе.** В гайдбуке его нет,
поэтому область применения ровно одна: прорастающий знак в фоне первого экрана
(`--brand-gold-62`, раньше был приглушённый Sage). Оттенок тёплый и
приглушённый, не жёлтый металлик: знак лежит на зелени мха под тёплым белёсым
светом лучей, и чистое золото рядом с ними выглядит наклейкой. Как и лайм,
живёт **только на тёмном**: по Ink это 8.4:1, по Cream — 1.9:1. Появится ещё
где-то — это уже не акцент, а пятая краска в четырёхцветной палитре.

### Почему приглушённые оттенки — готовыми `rgba`

Запись `text-[color:var(--brand-cream)]/65` **невалидна**: Tailwind пытается
разложить переменную на каналы, а там лежит готовый hex. Правило выбрасывается
целиком — проверено по собранному CSS, класса там нет вообще. Цвет молча
наследуется. Поэтому под каждую нужную прозрачность заведён свой токен:
`--brand-cream-72`, `--brand-moss-40` и т. д.

**Никогда не пишите `/NN` после `var()`-цвета.** Нужен новый уровень — заведите
токен.

## 4. ВИЗУАЛЫ ПЕРВОГО ЭКРАНА

### Логотип и росток — одна геометрия

Знак в шапке и растение, которое прорастает при прокрутке, — **один и тот же
рисунок** в двух размерах. Иначе они разъезжаются при любой правке.

### Лучи света (`LightRays`) — фрагментный шейдер

Основа: CodePen [«2025-08-10 light rays»](https://codepen.io/loiclaudet/pen/XJmawJg)
(Loïc Laudet, MIT, лежит в `2025-08-10light-rays/`), сам он по мотивам
ElusivePete на Shadertoy. **Заменил всю прежнюю CSS-механику лучей.**

**Почему шейдер.** Столб света — не фигура, а ПОЛЕ яркости: она зависит от угла
к солнцу и расстояния до него в каждой точке кадра. CSS рисует фигуры, поэтому
там луч собирался из двух прямоугольников, клина-обрезки, маски-колокола и
размытия — и всё равно оставались стыки, ступеньки и пересчёт `blur` на каждом
кадре. Здесь яркость считается прямо для пикселя, а анимация — сдвиг фазы
синуса, то есть ровно то самое плавное свечение.

**Что изменено против оригинала и зачем:**

| Правка | Причина |
|---|---|
| Источник вынесен в uniform, стоит за правым верхним углом | по центру сверху он не для этой композиции |
| Вершина ПОДНЯТА над кромкой (`sy` ≈ −0.15) | видимая точка схода читается лампой; но уносить далеко нельзя — см. ловушку ниже |
| Добавлено затухание с расстоянием | в оригинале фон чёрный и ровная засветка кадра выглядит туманом; у нас под лучами заголовок |
| Добавлен порог `(raw − 0.58)` | в оригинале яркость не падает до нуля, промежутки между лучами светлые, и пучок читается сплошным конусом |
| Добавлен ореол `u_glow` | пятно солнца |
| Холст ПРОЗРАЧНЫЙ, альфа = яркость | см. ловушку ниже |
| Половинное разрешение + 30 к/с | страховка для машин без аппаратного ускорения |

**Ловушка 1: частоты связаны с положением вершины.** Рисунок задан через
косинус угла на точку кадра. Унесёшь источник далеко за край — угол по всему
кадру почти не меняется, синус успевает сделать пол-колебания, и вместо веера
остаётся ОДИН размазанный луч. Проверено: `sy ≈ −0.35` уже даёт ровно это.
Двигаешь вершину дальше — поднимай частоты (`36.2 / 21.1`) пропорционально.

**Ловушка 2: непрозрачный холст ЗАКРАШИВАЕТ кадр, а не смешивается.** Сначала
холст был непрозрачным по образцу оригинала (там под ним чёрная страница, и это
незаметно), с расчётом на `mix-blend-mode: screen` у контейнера — screen с
чёрным ничего не меняет. На деле кадр потемнел: замер дал слева `rgb(4,4,3)`
против `rgb(34,40,26)` без лучей. Лечится не подбором режима смешивания, а
прозрачным холстом: альфа = яркость света, цвет умножен на неё
(`premultipliedAlpha`), плюс `gl.clear` каждый кадр — иначе свет копится в
грязное пятно.

### Моховой фон (`MossBackdrop`) — броуновское движение

Основа: CodePen [«Moss by Brownian Motion»](https://codepen.io/DonKarlssonSan/pen/mWqjqO)
(Johan Karlsson, MIT, лежит в `moss-by-brownian-motion/`). Сто точек блуждают
случайным шагом и оставляют едва заметные штрихи; холст никогда не очищается,
поэтому фон медленно зарастает.

Лежит ПОВЕРХ фотографии героя, а не вместо неё: фотография держит объём и план,
холст добавляет живую фактуру. Один холст без фотографии — равномерный шум.
Едет тем же параллаксом, что и фотография, иначе фактура поплывёт по
неподвижному кадру.

**Что изменено против оригинала:**
- p5.js не подключается: 300 КБ ради ста частиц и отрезков — это чистый canvas 2D.
- Холст прозрачный, а не чёрный: под ним фирменный Ink.
- Шагов за кадр 8, а не 50 — фон должен зарастать МЕДЛЕННО.
- Есть предел `MOSS_FILL_FRAMES`: после него цикл останавливается совсем, иначе
  холст зарастает в сплошное пятно, а процессор занят вечно.
- Оттенки сгруппированы в шесть корзин — см. ниже, это про скорость.

**Ловушка: `stroke()` на каждый штрих — главный расход страницы.** В оригинале
у каждой частицы свой оттенок, то есть свой вызов: сто частиц на восемь шагов =
800 вызовов за кадр. Замер прокрутки на реальном GPU: **59 кадров** за 2.2 с
против 131 без холста. С шестью корзинами штрихи одного оттенка собираются в
один путь: 48 вызовов вместо 800. На глаз шесть зелёных на полупрозрачных
штрихах неотличимы от ста.

### Замеры прокрутки (2.2 с, 2200 px, 1440×900)

| Состояние | Кадров | p95 |
|---|---|---|
| Всё включено | 158 | 41 мс |
| Без мохового холста | 168 | 33 мс |
| Без лучей | 165 | 34 мс |
| Без обоих | 156 | 34 мс |

То есть после чистки эффекты практически бесплатны.

**Мерить ОБЯЗАТЕЛЬНО с аппаратным ускорением.** Playwright по умолчанию
поднимает headless Chromium на SwiftShader (программный рендер), и шейдер там
считает процессор: те же 158 кадров превращаются в 38. Проверять так —
`chromium.launch({ args: ["--use-angle=metal", "--ignore-gpu-blocklist"] })`,
а убедиться можно строкой `UNMASKED_RENDERER_WEBGL`.

### Контраст первого экрана

Свет бьёт в правый верхний угол, где стоит шапка, поэтому контраст там держится
не «на глаз», а замером (текст прячется, снимается фон под ним):

| Что | Фон | Контраст |
|---|---|---|
| Ссылки шапки | `rgb(101,96,53)` | 5.67:1 |
| Почта в верхнем ярусе | `rgb(53,53,36)` | 11.08:1 |
| Заголовок h1 | `rgb(60,66,36)` | 9.37:1 |

Два места, которые это держат, и оба ослаблять нельзя без пересчёта:
- **подложка первого экрана** `.94/.80/.38` → `.88/.68/.24` (осветлена по просьбе);
- **подложка шапки**, пока она не прилипла. Раньше там был `bg-transparent`, и
  после осветления ссылка «Contact» дала **2.99:1 — провал AA**. Теперь мягкая
  тень сверху вниз: подписи держит, панелью не читается.

### «Водяная батарейка» (`WaterBattery`)

Визуал блока Flagship product **сознательно оставлен вне брендовой палитры**:
синяя вода и лаймовый акцент `#C3D45F`. При переводе на Sage вода переставала
читаться водой. Лайм возвращён **по всей секции**, а не только в батарейке, —
иначе метрики сверху остаются Sage и внутри одного блока два разных акцента.

Анимации (все выключаются при `prefers-reduced-motion`):
- волна на поверхности — сдвиг ровно на период, петля бесшовная;
- шесть пузырьков **внутри водяного слоя**: анимируется `bottom` в процентах, а
  не `translateY` в px, потому что колба меняет высоту и по брейкпойнтам, и по
  прокрутке;
- пульсация капли в кольце.

## 5. ГРАБЛИ

Все пять уже стреляли в этом проекте. Четыре из пяти — **молча**.

### 5.1 `str.replace` без ограничения количества

Самая частая ошибка сессии, поймана трижды. Питоновский `replace` меняет **все**
вхождения. Якорь `@media (prefers-reduced-motion)` встречается в файле дважды —
весь блок CSS вставился двумя копиями (~4 КБ мёртвого кода). Световое пятно тем
же способом попало в светлячков и мотыльков.

Хуже: при **промахе** `replace` молча ничего не делает. Так правило выключения
анимаций не попало в файл вообще, и анимации не отключались при
`prefers-reduced-motion` — обнаружено только замером.

**Правило:** после каждой замены `assert` на вхождение и проверка счётчика.

### 5.2 Прозрачность на `var()`-цвете

См. §2. Класс не попадает в CSS, цвет наследуется. Не видно ни по типам, ни по
консоли — только по собранному CSS или скриншоту.

### 5.3 Специфичность в блоке reduced-motion

`.sph .ray { animation: none }` (два класса) проигрывает базовому
`.sph .light-rays .ray` (три класса). Луч продолжал мигать. Селектор выключателя
должен быть **не короче** базового.

### 5.4 `next build` при запущенном `next dev`

Оба используют каталог `.next`. Итог: «Build error occurred» на ровном месте и
dev-сервер отдаёт побитую страницу — секция выглядит пустой, хотя разметка цела.

**Лечение:** остановить dev, `rm -rf .next`, пересобрать.

### 5.5 CI падал на `typecheck` при зелёной локальной проверке

`next-env.d.ts` в `.gitignore` — в чистом клоне его нет, создаёт его сам
`next build`. Он объявляет типы для импорта картинок. Пока `typecheck` стоял в
workflow **до** сборки, CI падал на `TS2307: Cannot find module
'./assets/moss-ledge.png'`, а локально файл оставался от прошлых сборок.

**Лечение:** в `.github/workflows/deploy.yml` сборка идёт **первой**, typecheck
после неё. Не менять местами.

### 5.6 Двойной слэш в путях к картинкам

`assetPrefix` был с хвостовым слэшем, Next склеивал его с `/_next/...` и
статически импортированные картинки получали `/sphgnm//_next/...`. GitHub Pages
это прощает, другой хостинг отдаст 404. Слэш убран.

## 6. КАК ПРОВЕРЯТЬ

Скриншота мало: половина дефектов выше видна только замером.

```bash
npm run typecheck
GITHUB_PAGES=true npm run build      # НЕ при запущенном dev
```

Через Playwright обязательно снимать:

- `document.documentElement.scrollWidth - clientWidth` — должно быть **0** на
  1440 и 390;
- `pageerror` и `console.error` — пусто;
- `getComputedStyle(el).animationName` при `reduced_motion="reduce"` — должно
  быть `none` у **каждой** анимации;
- `getComputedStyle(el).transform` дважды с паузой — там, где элемент обязан
  стоять на месте.

После пуша деплой проверяется по API, а не «на глаз»:

```bash
curl -sS "https://api.github.com/repos/lemnity/sphgnm/actions/runs?per_page=1"
```

Зелёный workflow ≠ обновившийся сайт: Pages отдаёт новую сборку с задержкой.
Убеждаться поиском новой разметки в живом HTML.

## 7. ОТКРЫТЫЕ ВОПРОСЫ

### 7.1 Палитра прислана противоречивой

В присланной картинке **три подписи из пяти не совпадают со своими плашками**:

| Плашка | Подпись | Чем на самом деле является подпись |
|---|---|---|
| зелёная | `#662D91` | фиолетовый |
| чёрная | `#141816` | совпадает |
| лаймовая | `#92EAF2` | голубой |
| фиолетовая | `#BAE14B` | лайм |
| тёмно-зелёная | `#3E5042` | совпадает |

Из набора взят только лайм `#BAE14B` — по прямому указанию, на бабочки.
Остальное не трогалось. Нужно решить: ориентироваться на плашки или на подписи.

Отдельно: **в наборе нет Cream `#F4F1EA`**, а это сейчас фон большей части
сайта (по гайдбуку — 65%). Оставляем его или светлые секции уходят в белый?

### 7.2 Вес картинки

`components/assets/moss-ledge.png` — 1.7 МБ, уже в истории git. На первый экран
это заметный вес; `next/image` в проекте не используется, PNG отдаётся как есть.
WebP того же кадра обычно даёт 200–400 КБ без видимой потери.

### 7.3 Форма никуда не отправляется

`onSubmit` только показывает подтверждение. Приём заявок нужно подключать
отдельно.
