# Почему так сделано

README описывает, как с проектом работать. Здесь — решения, которые неочевидны
из кода, и ловушки, на которые уже наступали. Перед правкой визуала или сборки
стоит пробежать раздел «Грабли»: большинство из них не видно ни по типам, ни
в консоли.

## Палитра

Токены — в `components/sphagnum-styles.tsx`, блок `.sph`.

| Токен | Hex | Где |
|---|---|---|
| `--brand-ink` | `#102B20` | тёмные секции, текст на светлом |
| `--brand-cream` | `#F5F4F0` | светлые секции, текст на тёмном |
| `--brand-moss` | `#3E5042` | акцент и кнопки **на светлом** |
| `--brand-sage` | `#8AA18A` | акцент **на тёмном** |
| `--brand-gold` | `#D7B15E` | кнопка первого экрана, галерея, раздел «Why us» |
| `--brand-lime` | `#BAE14B` | только на тёмном |

Контраст (WCAG):

| Пара | Контраст | |
|---|---|---|
| Cream по Ink | 13.7:1 | да |
| Sage по Ink | 5.4:1 | да |
| Moss по Cream | 7.8:1 | да |
| Ink по Gold | 7.4:1 | да |
| **Sage по Cream** | **2.5:1** | **нет** |
| **Gold по Cream** | **1.8:1** | **нет** |
| **Lime по Cream** | **1.4:1** | **нет** |

Отсюда правило: на светлом акцент — Moss, на тёмном — Sage, золото или лайм.
Золотой фон — только с тёмным текстом. Поменять местами нельзя: мелкий текст
станет нечитаемым.

Золота и лайма в гайдбуке нет, это осознанные исключения. Каждое новое место
для них — уже не акцент, а пятый цвет в палитре.

Приглушённые уровни заведены готовыми `rgba` (`--brand-cream-72`, `--brand-ink-85`…),
потому что `text-[color:var(--brand-cream)]/72` не работает — см. «Грабли».

## Типографика

Весь сайт набран одним системным гротеском (`Arial, Helvetica`) — так свёрстан
PDF-референс. Иерархия держится размером и насыщенностью, а не сменой гарнитуры.
`verify:layout` проверяет, что на странице ровно одно семейство: случайно
подключённый веб-шрифт сразу всплывёт.

Заголовки — строчными. Капс оставлен только мелким меткам (`.label`) и кнопкам.

## Первый экран

**Живая фотостена** (`LivingWall` в `sphagnum-visuals.tsx`). Листва на фотографии
шевелится под курсором — WebGL-шейдер со смещением по шумовой сетке размером
примерно в лист.

- Холст лежит поверх обычного CSS-фона с той же картинкой и показывается только
  после первого удачного кадра. Нет WebGL, не загрузилась текстура, включено
  «меньше движения» — виден статический фон, пустого экрана не бывает.
- Кадрирование холста (`cover`, привязка к низу, на узком экране — к левому краю)
  обязано совпадать с `background-position` подложки, иначе картинка прыгнет
  в момент появления холста. Порог 1024 px задан в двух местах:
  `sphagnum-landing.tsx` и `LivingWall`.
- Смещение умножается на «зелёность» пикселя: мраморная стойка, рамы и пол не
  должны колыхаться вместе с листьями.
- Цикл отрисовки крутится, только пока догорает «энергия» от движения курсора;
  в покое стена статична и не тратит кадры.

**Затемнение под текстом** — глубокий зелёный, а не серый: серая пелена уводила
фотографию в хаки. Справа оно сходит на нет рано, чтобы стена не тускнела.
Контраст под текстом держит начальный стоп градиента, а не средний. Меняете стопы
или яркость кадра — замерьте контраст по реальному фону под строкой заново.

**Тонировка** (`HERO_BG_FILTER`) задаётся одной константой для подложки и холста.

## Остальная страница

- **Галерея** — masonry по рядам: элемент `i` уходит в колонку `i % columns`.
  CSS columns заполняли бы колонки сверху вниз, и порядок «новые → старые»
  читался бы столбцами. Ролики в плитках без звука, по кругу; начинают грузиться,
  когда плитка впервые попадает на экран.
- **Экран загрузки** — по мотивам CodePen tree-loader (MIT). Автор разрешает брать
  код, но не рисунок, поэтому взята только механика, силуэты нарисованы заново.
- **Появление блоков** (`Reveal`) отключается при `prefers-reduced-motion`: контент
  сразу видим. Без IntersectionObserver блок тоже показывается сразу.
- **Иллюстрации карточек решений** вырезаны из PDF скриптом
  `scripts/extract-solution-artwork.mjs` с мягкой альфа-кромкой по пустому фону.
- В `sphagnum-visuals.tsx` и `sphagnum-styles.tsx` остались прежние варианты
  оформления (шейдерные лучи, моховой холст, «водяная батарейка», светлячки).
  Страница их не использует; при чистке удалять вместе со стилями.

## Контент и кабинет

- **Контент в JSON-файлах, без базы.** Один редактор, редкие правки, сайт должен
  собираться в статику для Pages — файлы в репозитории покрывают всё это.
  Структуру держит схема `lib/content/schema.ts`; по ней же тест сверяет поля
  редактора (`lib/admin/fields.ts`), так что новое поле схемы не пропадёт из
  кабинета молча.
- **Кабинет только в серверном режиме.** Его файлы называются `*.admin.ts(x)`, и
  `next.config.mjs` добавляет это расширение в `pageExtensions` только без
  статической сборки. В `out/` кабинета и API нет вообще, а не «спрятаны».
- **Запись атомарная** (временный файл + rename), прежняя версия уходит
  в `content/.history/`. Сохранения идут по очереди, метки версий строго
  возрастают — два сохранения в одну миллисекунду не затирают друг друга.
- **Вход** — подписанная cookie (HMAC, без хранения на сервере). Выход только
  стирает cookie: украденный токен живёт до конца срока или до смены
  `ADMIN_SESSION_SECRET`.
- **Лимит попыток** считается по IP только при `ADMIN_TRUST_PROXY=1`: без своего
  прокси заголовок `X-Real-IP` подделает кто угодно. Цена — без флага счётчик
  общий на всех, и чужой перебор закрывает вход владельцу.
- **Загрузки**: тип определяется по первым байтам, а не по имени и MIME; SVG
  запрещён (в нём может быть скрипт); имя случайное. Файлы, загруженные после
  `next start`, отдаёт роут `/uploads/…` с поддержкой Range — без неё Safari не
  проигрывает видео.

## Грабли

### Прозрачность на `var()`-цвете

`text-[color:var(--brand-cream)]/85` собирается в невалидный CSS: в переменной
готовый hex, разложить его на каналы Tailwind не может. Браузер выбрасывает всю
декларацию, и цвет молча наследуется — тёмный текст на тёмном фоне. Видно только
по собранному CSS или скриншоту. Нужен новый уровень — заведите токен.

### Специфичность выключателей анимации

Правило в блоке `prefers-reduced-motion` должно быть не короче базового
селектора: `.sph .ray { animation: none }` проигрывает `.sph .light-rays .ray`,
и анимация продолжается.

### Обратные кавычки в `sphagnum-styles.tsx`

Весь CSS — внутри template literal. Обратная кавычка или `${` в комментарии
ломает файл.

### `next build` при запущенном `next dev`

Оба пишут в `.next`. Сборка падает, а dev-сервер начинает отдавать страницу
с пустыми секциями. Остановить dev, удалить `.next`, пересобрать.

### Порядок шагов в CI

`next-env.d.ts` в `.gitignore` и появляется только после `next build`, а в нём
объявлены типы импорта картинок. Поэтому в `deploy.yml` сборка идёт до typecheck,
иначе чистый клон падает на TS2307.

### Хвостовой слэш в `assetPrefix`

С ним импортированные картинки получали `/sphgnm//_next/...`. Pages это прощает,
другой хостинг отдаст 404.

### Тело запроса через middleware

`middleware.admin.ts` стоит перед `/api/admin/upload`, а Next по умолчанию
пропускает через middleware только первые 10 МБ тела. Видео крупнее приходило
обрезанным. Лимит поднят `experimental.middlewareClientMaxBodySize` в
`next.config.mjs`; на сервере ещё нужен `client_max_body_size` в nginx.

### Источник публикации Pages

Должен быть «GitHub Actions». При «Deploy from a branch» параллельно работает
Jekyll-деплой, и по адресу попеременно оказывается то сайт, то README.

### Массовые замены в тексте

`str.replace` без проверки числа вхождений уже дважды вставлял блок CSS двумя
копиями, а при промахе молча ничего не менял. После автоматической замены
проверяйте, сколько вхождений нашлось.

## Как проверять

- `npm run typecheck`, `npm test`.
- `verify:layout` на запущенном сервере — порядок блоков, сетка 1550 px,
  переполнение на 1685 / 834 / 390, мобильное меню, галерея, reduced-motion.
- `verify:admin` — сквозной сценарий кабинета.
- Перед выкладкой — `GITHUB_PAGES=true npm run build` при остановленном dev.
- Замеры производительности анимаций — только с аппаратным ускорением: headless
  Chromium по умолчанию рисует WebGL программно, и цифры получаются в разы хуже.
  `chromium.launch({ args: ["--use-angle=metal", "--ignore-gpu-blocklist"] })`.
- После пуша проверять не зелёный workflow, а живой HTML: Pages отдаёт новую
  сборку с задержкой.

## Открытые вопросы

- **Снижение полива.** В тексте блока Applications и в FAQ — «60–80%», в подписи
  под иконкой «Less irrigation» — «Up to 50–80%». Нужна одна цифра из источника.
- **Палитра.** В присланной картинке палитры подписи части плашек не совпадают
  с их цветом; из набора взят только лайм `#BAE14B`.
- **Логотип и название:** `SPHAGNUM AE` в логотипе, `Sphagnum Eco` в текстах.
- **Форма заявки** не отправляется — нужен приём заявок.
